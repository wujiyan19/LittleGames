# Mate 60 Pro 真机问题记录

日期：2026-09-30。设备 Mate 60 Pro，用户提供系统 7.0.0.709 SP6，调试工具报告 API 26。候选包为 1.0.0 / API 24 Debug，SHA-256 `5197B4A2F4ECDD0CC1DEF672A80B2254309F06EB9644F0773F05B2F643F3679C`。

以下结论来自设备上的触控输入、画面和界面布局；自动检查过程中发生的文字识别、棋盘坐标排序与等待时机错误已经单独重试，不作为产品缺陷。

## P1：记忆卡片显示与实际判定不一致（两款游戏）

**记忆缺项复现**：从分类打开游戏，看到 `3、8、12、11、15`，点击“记好了”。画面剩下 `3、8、12、11`，因此选择消失的 `15`。应用提示“上一题正确答案：12”，这一题不加分。所见内容不能作为作答依据。

证据：[记忆阶段](../screenshots/bug-mate60-missing-q0-before.jpeg)、[消失后的画面](../screenshots/bug-mate60-missing-q0-after.jpeg)、[作答反馈](../screenshots/bug-mate60-missing-q0-feedback.jpeg)。数值和反馈还保存在玩法检查点中。

**顺序记忆复现**：新开游戏显示 `7、5、9、7、7、7`，点击顶部重新开始，仍显示同一组。点击“记好了”，按显示顺序输入，出现“本局结束”，得分 0。首次进入的一局已验证可以按所见序列完成；本问题在重新开始后复现。

证据：[重开前](../screenshots/bug-mate60-memorysequence-before.jpeg)、[重开后的序列](../screenshots/bug-mate60-memorysequence-restarted.jpeg)、[按画面输入后失败](../screenshots/bug-mate60-memorysequence-recall.jpeg)。

代码审阅推断：`CollectionPage.ets:274–285` 的 `MemoryCards()` 按索引复用卡片，而卡片文字来自构建回调参数 `value`。删除中间数字、切换题目或重新开始时，索引不变的节点可能保留旧值。建议使卡片内容随实际数字和题目更新，修复后在真机复测连续十题、删除中间数字、重复数字、顶部重开和结果页重开。此处是结合代码的原因推断，尚未通过修复版本验证。

## P1：华容道棋块移动不更新画面

普通难度初始布局，选择最左侧下方的兵，它的右方和下方均为空位。分别点击右、下方向键，棋块画面仍停在原来的格子；选中与移动后的棋块中心坐标没有变化。此前尝试按可见布局执行合法通关步骤也未能完成。

证据：[操作前](../screenshots/bug-mate60-klotski-before.jpeg)、[选择棋块](../screenshots/bug-mate60-klotski-selected.jpeg)、[向右](../screenshots/bug-mate60-klotski-right.jpeg)、[向下](../screenshots/bug-mate60-klotski-down.jpeg)。布局证据保留全部棋块坐标，比较使用中心位置，排除了按压缩放造成的边界差异。

代码审阅推断：`KlotskiPage.ets:98–116` 按固定 `piece.id` 复用节点，而位置、选中状态和点击参数来自 `piecesForView()` 每次生成的普通对象。建议将每块棋子的显示状态与触控定位绑定到持续可观察的数据，避免复用旧的坐标快照。修复后复测移动、取消选择、连续移动、切换难度及通关。尚未安装修复版本验证原因。

## P2：扫雷旗格中心长按不能取消，边缘可以

初始左上格长按，旗数 `0/10→1/10`。短按旗格没有揭开，符合预期。随后在同一格中心长按三次，旗数一直为 `1/10`。在同一格靠左上边缘长按，旗数变成 `0/10`。检查使用相同设备输入工具，改变的只有触点位置。

证据：[插旗](../screenshots/bug-mate60-mine-flagged.jpeg)、[中心第一次](../screenshots/bug-mate60-mine-center-0.jpeg)、[中心第二次](../screenshots/bug-mate60-mine-center-1.jpeg)、[中心第三次](../screenshots/bug-mate60-mine-center-2.jpeg)、[边缘取消](../screenshots/bug-mate60-mine-edge.jpeg)。首点安全、踩雷结算和重新开始另外验证通过。

建议检查 `MinesweeperPage.ets:183–191` 中旗帜图片出现后的命中区域和父格长按手势，使整格都能取消旗帜。修复后补验中心、四角、连续插旗/取消、已揭开格长按，以及人手长按体验。

## P2：设置选中标记没有立即更新

初始设置为“跟随系统、普通”。依次点击“深色”和“困难”，应用外观已经变深，但选中标记仍落在“跟随系统”和“普通”；等待后仍不更新。退出设置再进入，标记才变为“深色”和“困难”。冷启动也显示新选择；新开的猜数字确实使用五位密码，说明偏好已经保存，当前页面的反馈没有同步。

证据：[初始值](../screenshots/public-mate60-settings-original.jpeg)、[切换后](../screenshots/public-mate60-settings-changed.jpeg)、[等待后仍显示旧标记](../screenshots/public-mate60-settings-stale.jpeg)、[重新进入后](../screenshots/public-mate60-settings-reentered.jpeg)、[困难新局](../screenshots/public-mate60-default-hard.jpeg)。深色画面中原选中按钮的文字也不易辨认，应一并复核其颜色状态。

建议检查 `SettingsPage.ets:102–121` 的 `Choice()` 中以构建参数生成的选中图标、背景、文案颜色及无障碍描述，确保它们随当前偏好立即更新。恢复后的[浅色画面](../screenshots/public-mate60-settings-restored.jpeg)也存在选中项蓝字蓝底、对比度偏低的现象；`DesignTokens.ets:33–36` 将文字与激活背景分别映射为系统强调色与激活组件色，应按实测背景核对搭配。上述行号以本轮工作区为准。主题和默认难度已恢复并通过重新进入设置核对。

## P2：“最近玩过”列表返回后不及时刷新

在“我的”中，最近列表以俄罗斯方块开头。进入猜数字并返回“我的”，列表仍为“俄罗斯方块、贪吃蛇、跳一跳、打砖块、打地鼠”。强制结束应用并重新打开后，变为“猜数字、俄罗斯方块、贪吃蛇、跳一跳、打砖块”。新记录被保存，但温启动页面没有反映最新进入顺序。

证据：[本轮进入猜数字](../screenshots/public-mate60-default-hard.jpeg)、[返回后旧顺序](../screenshots/public-mate60-profile-recent-after-game.jpeg)、[冷启动后正确顺序](../screenshots/public-mate60-profile-recent-relaunch.jpeg)。最高分、排行榜与游戏数量另已验证保留，没有将此问题描述为战绩丢失。

代码审阅方向：`Index.ets:114–145` 的刷新依赖页面显示，而导航返回和页签切换也需触发及时更新；`ProfileTab.ets` 的最近列表接收父组件参数。建议核对返回游戏页后概要刷新是否真正执行，并复测最近顺序、游玩次数、最高分及热门列表。原因尚未通过修复版本验证。

## 后续开发优先级

先修复记忆卡片和华容道两处主要玩法问题，再处理旗格触点、设置反馈及最近列表更新。本轮五类问题均需以真机复测结果关闭；现有 313 项桌面规则测试通过，仍然漏过了这些界面问题。建议补充相应的真机界面回归，不仅检查模型返回值。

补充代码审阅意见：`GameHeader.ets:70` 仅在 `subtitle` 为非空字符串时显示副标题，但页面传入的多处副标题为资源引用。真机华容道页头没有显示步数。建议统一支持资源副标题，并检查猜数字尝试数、记忆翻牌配对进度等信息是否完整。此项不与玩法阻断问题混为一项。
