# ClashBox 前端设计研究与玩趣盒美化方案

研究日期：2026-10-07。参考仓库为 [xiaobaigroup/ClashBox 的 master 分支](https://github.com/xiaobaigroup/ClashBox/tree/master)，下载快照的 ZIP 注释确认提交为 `e036a6a3097192ff74987ce7306eea2a03d6a3ac`。下方链接固定到这一提交，便于复查。

## 研究范围与结论

本次阅读主页面、主页卡片、设置/外观页、导航与悬浮栏、动画工具、断点参数、主题资源和 UIConfig，并对照玩趣盒当前代码及项目内历史验收截图。未修改应用源码。

ClashBox 的主要设计特色可以归纳为：**中性页面底色、实色圆角卡片、局部强调色、按任务分层的导航、响应窗口形态的布局，以及明确的触摸反馈。** 它的统一感来自重复使用同一组容器与排版规则。

首次研究基于源码；随后已连接手机，完成下方的2.1.0实机复核。`xb_components` 是 Git 子模块，当前源码包中的目录为空；[.gitmodules](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/.gitmodules#L7) 指向 Gitee。可以检查调用方式，但不能确认其内部主题管理、部分断点函数和动画包装的实现。这个限制不等于组件库未公开。

## 实机复核：哪些符合，哪些需要修正

2026-10-07连接手机后，读取到安装版本ClashBox **2.1.0 / versionCode 2010016**，截图原始分辨率1260×2720。观察了首页、更多页、搜索弹层、设置及外观子页、主题菜单、深色外观、滚动收放导航、横滑进入代理页，并对照同一手机上的玩趣盒首页。

**结论：主体设计方向符合；具体间距、材质和图标用色需要按2.1.0实机补充。** 后续章节的20vp圆角等数值仍是旧master源码证据，不能等同于2.1.0的实测规格。

| 学习点 | 实机结果 | 玩趣盒应如何借鉴 |
| --- | --- | --- |
| 浅灰底＋白色主卡 | 符合。首页UI树有页面`#FFF1F3F5`和主卡`#FFFFFFFF` | 主卡应使用独立表面色，避免大面积灰色覆盖 |
| 主体、内部控件、圆形按钮、胶囊导航分层 | 符合观感 | 建立按角色区分的圆角规格；20/24/12vp仍是提案值 |
| 双列小卡＋跨列重点卡 | 符合。小卡近正方形，重点卡宽高比约2.07 | 游戏入口保留双列，重点位置突出继续游玩；不复制仪表盘的大块空白 |
| 主副文字与分组 | 符合。更多页和设置入口保持统一图标/文字/箭头位置；外观详情将相关项合组 | 统一对齐，重要说明用14fp，组内轻分隔线 |
| 单一强调色 | 符合角色分工，但不是所有图标都蓝 | 更多页图标主要黑色，设置图标蓝色；普通游戏信息保持中性，选中和动作再强调 |
| 模糊只在特定层级突出 | 符合。设置/搜索背后明显虚化，普通主卡为清楚实色面 | 重点是当前层与背景的关系；继续使用现有原生材质 |
| 横滑主分页与底栏同步 | 已操作确认：首页横滑进入代理页，底栏同步选中代理 | 主页面切换反馈可借鉴，游戏运行页避免全局横滑手势 |
| 向下滚收起、反向滚展开 | 已操作确认。底栏收成当前页图标，反向滚动恢复四入口 | 玩趣盒仍建议保持三个入口可见，提高分类可发现性 |
| 深色表面分层 | 已临时切换确认：黑底、较亮深色卡、浅色文字、蓝色强调 | 补齐应用深色表面资源，保持文字与背景可读 |
| 材质配置 | 2.1.0外观页有“沉浸光感材质”，当前值“沉浸光感”；另有“顶栏模糊效果” | 旧源码的手动blur实现不能代表新版全部材质实现；无需替换玩趣盒已有HDS基础 |

### 需要纠正的间距结论

当前首页左小卡为`[45,886][606,1447]`，右小卡为`[654,886][1215,1447]`：小卡561×561px，横间隙48px；连续两行卡片的纵间隙39px。当前实机因此是**横间隙略大于纵间隙**。旧源码x12/y15的“纵间距稍大”只适用于旧源码参数，不能直接套到当前版本。

更多页、设置入口的可见ListItem宽1176px、高182px，连续项间隔39px。UI树不提供fontSize、borderRadius和padding，不能把截图像素直接换算成vp/fp，也不能声称当前安装版的圆角仍精确为20vp。动画检查确认了操作与结束状态，没有测量帧率或给出性能结论。

### 同机对照后的第一优先级

玩趣盒当前UI树中，11个可见内容容器使用`#19000000`的半透明黑色背景，叠在`#FFF1F3F5`页面底色上，实际表现为大面积灰色；ClashBox主内容卡为白色。这个差异与截图一致，确认了原方案中的“减轻卡片视觉重量”。

因此先统一主卡表面色，再统一页面标题、内容对齐和间距。不是先增加阴影、渐变或更大圆角。当前玩趣盒已有悬浮导航和游戏图标，继续保留；游戏图标与棋盘承载趣味，页面表面负责清楚地组织内容。

检查结束后已恢复ClashBox原主题“跟随系统”，手机留在ClashBox首页。网络模式、节点和VPN开关没有被操作。原始界面证据保存在忽略的本地研究目录，文档只记录设计事实；复核摘要见[device-check.json](clashbox-design-review-2026-10-07/device-check.json)。

## 一、圆角与容器：按包含关系建立尺寸层级

| 对象 | 源码参数 | 设计含义 |
| --- | --- | --- |
| 主体卡片 | 20vp | 主页卡、设置入口、公共行等采用共同基准 |
| 收藏节点、快捷方式内部条目 | 10vp | 小容器位于大卡片内，曲率随尺寸减小 |
| 模式选择滑块 | 18vp | 贴合内部胶囊控件 |
| 悬浮导航 | 高60vp、圆角30vp | 完整胶囊形态，表达独立浮动操作层 |
| 返回按钮 | 40×40vp、圆形 | 独立工具操作，与信息卡片区分 |

证据：[Constants](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/common/entity/Constants.ets#L17)、[HomeCard](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/pages/HomePage.ets#L627)、[设置入口行](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Settings/settingsListItem.ets#L55)、[悬浮栏](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Common/FloatBar.ets#L114)、[返回标题栏](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Settings/TopBuilder.ets#L25)。

不能把它总结成“所有东西都是20圆角”。设置首页 List 本身有18圆角，而内部入口行仍为20；控件与容器是不同层级。

## 二、间距：主页栅格与设置列表采用不同节奏

重要参数集中在 [BreakPoint.ets](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/common/breakpoint/BreakPoint.ets#L155)。

| 对象 | 手机常见参数 | 宽屏变化 |
| --- | --- | --- |
| 主页卡片内部 | 上12、下18、左右14vp | 各边增加；下侧始终比上侧宽 |
| 卡片间距 | 横12、纵15vp | 部分大屏断点横17.6、纵22vp |
| 主页外侧留白 | 按高宽组合为14或25vp | 可增加到25、50、100vp |
| 更多/设置外侧留白 | 普通手机15vp，低比例窗口12vp | 一般16vp |
| 设置入口之间 | 10vp | List 固定间距 |
| 设置行主副文本之间 | 2vp | 用字号和颜色补充层级 |
| 设置行图标到文字 | 10vp | 左侧图标另留12vp边距 |

有两个值得学习的细节：纵向间距稍大于横向，便于逐行阅读；卡片下方内边距稍大，让内容不贴底。它没有严格使用4/8倍数体系，因此不能把所有观察值重写成一套不存在的“8点网格”。

玩趣盒可以采用更便于维护的资源尺度：4/8/12/16/20/24/32vp，再按页面角色选取；无须复制17.6等具体数值。

## 三、配色与材质：把内容面和浮动层分开

| 角色 | ClashBox 浅色 | ClashBox 深色 |
| --- | --- | --- |
| 页面背景 | `#F1F3F5` | `#000000` |
| 主卡片背景 | `#FFFFFF` | `#1A1A1A` |
| 内部小控件背景 | 低透明度黑色 | 低透明度白色 |
| 浮栏背景 | 带透明度的页面色 | 带透明度的黑色 |
| 文字 | 系统一级/二级文字色 | 同一语义资源随主题调整 |
| 当前项/操作 | 统一主题强调色 | 对应深色主题的强调色 |

来源：[浅色资源](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/resources/base/element/color.json#L12)、[深色资源](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/resources/dark/element/color.json#L12)。ArkUI 色值中带8位的写法是对应资源的透明度表达，迁移到其他渲染环境时需注意格式。

默认主题是 `blueAppTheme`，并提供多种主题色；它不是固定橙色风格。[UIConfig](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/entryability/AppState.ets#L76) 将主题、模糊、动效等偏好持久化。

真实主页卡片没有统一模糊或阴影。主要依赖白色/深色实色面与页面底色区分。悬浮栏才使用 `backdropBlur(30)` 和 radius15、offsetY4 的阴影；窗口模式另有背景模糊。外观设置里的预览卡片有额外效果，不能用它推断全部真实卡片。

对玩趣盒最有价值的迁移是：分清页面底、主卡片、卡片内控件和浮层四种角色，让强调色主要表达当前选择与动作。

## 四、字体与排版：信息重要性决定字号、粗细和颜色

| 位置 | 源码规格 |
| --- | --- |
| 代理、更多等大页面标题 | 常用30fp Bold |
| 主页问候标题 | 默认按字符数计算，`max(20, 33 - length)` |
| 主页卡片标题 | 手机通常16/18fp，大屏可到24fp，Bold |
| 设置入口标题 | 17fp Medium |
| 设置入口说明和右侧状态 | 14fp，系统二级文字色 |
| 设置/半模态标题 | 20fp Bold |
| 设置标题副文本 | 12fp |
| 导航标签 | 普通导航按断点为12～16fp；悬浮栏具体字号由子模块函数提供 |

证据：[标题栏](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Common/TopBar.ets#L36)、[动态字体工具](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/common/utils/CalculateFontSizeUtil.ets#L3)、[设置行文字](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Settings/settingsListItem.ets#L26)、[卡片标题](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Home/CardTitleBuilder.ets#L27)。

字重不是全页面统一加粗。标题负责引导，说明负责解释，右侧状态负责补充；同一行不会让所有元素都抢眼。

玩趣盒短页面名可以用稳定字号，无须照搬按字数缩小的问候语算法。长标题优先合理换行和省略，重要说明建议14fp，纯元数据才用12fp。

## 五、分页与导航：一级目的地、页内分类、详情操作各用一层

```text
Index：全局 Navigation 与状态装配
├─ 普通样式：Tabs
└─ 悬浮样式：Swiper + FloatBar
   ├─ 首页：卡片仪表盘
   ├─ 代理：横向分类 List + 内层 Swiper
   ├─ 配置：响应式卡片列表 + 编辑 Sheet
   └─ 更多：入口列表 + Navigation Stack / Split
                         └─ 设置 Sheet + 子页面返回栈
```

### 一级分页

[Index](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/pages/Index.ets#L411) 根据样式选择两套实现。默认悬浮模式是内容 `Swiper` 与浮栏共用控制器；不循环、不显示圆点。点击底栏和内容分页同步到 `tabCurrentPage`。普通 Tabs 则在点击、改变、动画开始时更新同一索引。

这里的“分页”是目的地切换，不是数字页码式分页；页内大量条目继续纵向滚动。已有底栏表达当前位置时，就没有再放一排分页圆点。

选中项使用主题色，普通 Tab 图标上移3vp，悬浮 Tab 图标上移2vp，文字和图标共同表达选择。

### 悬浮栏随滚动方向收放

[FloatBar](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/components/Common/FloatBar.ets#L66) 在手机滚动状态下只显示当前页60×60vp图标；点击图标可展开。各页通过滚动 offset 的正负设置 `isRolling`，因此它是向下滚收起、反向滚展开，不是停止滚动就自动展开。

左右还可外挂代理开关。这个布局服务于持续连接状态，玩趣盒没有同等需求时不必增加一个浮动播放开关。

### 页内分类

[代理页](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/pages/ProxyPage.ets#L178) 用55vp高横向 List 放分组，下方是内层 Swiper。选中分类通过主题实色、36vp高度体现，未选中为32vp；最小宽86vp，圆角20vp，文字14fp，右间距8vp。切页会让横向分类列表滚到当前项。

这层很适合转化为玩趣盒“全部/益智/休闲/棋类”等筛选。建议采用同高44vp触区、柔和选中背景，避免在选择时改变布局高度。游戏数量不必每个筛选都重复显示，当前分类名称和总数可独立放在内容上方。

### 详情与短操作

设置、配置编辑等采用原生 Sheet，常见档位684vp和 LARGE，优先 CENTER，打开时弱化背后内容。内部另有导航栈，返回按钮与关闭按钮分别负责退回上一层、离开整个浮层。更多页手机使用 Stack，宽屏使用 Split，分栏宽330vp。

不能把源码中的条件分支当作已经验证的运行行为：普通 Tabs 有 `isSecondary` 禁滑等条件，但本次没找到它被赋为true；代理分类边缘跳一级页调用的是普通 Tabs 控制器，不能推断默认悬浮模式也实现了同一行为。

## 六、响应式布局：窗口形态决定信息组织

实际 [EntryAbility](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/entryability/EntryAbility.ets#L718) 取系统窗口宽度断点，并用高宽比分类高度：小于0.79、0.79～1.2、至少1.2。随后二维参数表决定布局。

| 场景 | 源码中的设计变化 |
| --- | --- |
| 手机竖屏 | 底部导航、双列或跨列首页信息卡 |
| 手机横屏/较矮宽窗口 | 部分组合改侧边导航；减少垂直占用 |
| 更宽窗口 | 侧边导航、多列配置列表、更宽页面留白 |
| 更多页宽屏 | Stack 改为 Split，入口与详情并列 |
| 窗口模式 | 独立 PCIndex、工具尺寸和标题栏处理 |

仓库还有一套0/320/600/840/1000vp媒体查询封装，但不能把它当作当前入口实际使用的全部断点逻辑。部分悬浮布局函数属于未包含的 `xb_components`，具体数值无法确认。

它值得学习的是“变化信息结构”，而非把手机卡片无限拉宽。玩趣盒平板可以通过限宽、增加列数、设置双栏提升利用率；手机先保持明确的三个主入口。

## 七、动效与状态：反馈有一致语义，也有不宜照搬的实现

[Animation.ets](https://github.com/xiaobaigroup/ClashBox/blob/e036a6a3097192ff74987ce7306eea2a03d6a3ac/entry/src/main/ets/common/utils/Animation.ets#L17) 集中定义缩放、位移、透明度和弹簧转场；UIConfig统一动画开关与速度。默认自定义速度参数300ms，但不能据此断言所有原生分页滑动都固定300ms，弹簧本身也不能用duration概括。

| 行为 | 可确认实现 | 对玩趣盒的启发 |
| --- | --- | --- |
| 点击 | 原生clickEffect、scale0.95 | 游戏目录保留更轻的现有0.98卡片按压 |
| 列表进入 | 透明度+缩放+springMotion，按索引错峰 | 只用于少量首屏内容，避免长目录逐个弹出 |
| 标题/详情关联 | 部分geometryTransition | 重要返回与进入关系可保持连续 |
| 浮动功能按钮 | 从所在侧滑入，中央按钮渐隐 | 方向应解释来源，而非随机运动 |
| 图标进入 | 某些图标缩放0起并旋转360° | 不宜用于每个游戏入口的重复入场 |

它有部分滚动标题/浮栏动效直接改变height、width、padding、layoutWeight等布局参数，且本次未找到renderGroup调用。玩趣盒项目规则禁止动画过程中频繁改布局属性，因此只能借鉴意图，具体实现继续采用现有 `HarmonyMotion` 的scale/translate/opacity和复杂子组件renderGroup。

前端大量使用 `@Component`、`@StorageLink`、`@Provide/@Consume`，并将持久化偏好、运行状态、页面索引分开存放。这解释了主题与动画为何能跨页面保持一致；不需要把玩趣盒现有 `@ComponentV2` 和已拆分的页面重新并回一个全局大组件。

## 八、玩趣盒的具体美化方案

### 已有基础

玩趣盒已有系统语义色、深浅主题、HdsTabs悬浮导航、系统自适应/沉浸材质、响应式卡片网格及原生触摸反馈。应在这套基础上统一视觉规格。

当前源码显示普通游戏卡片与横幅圆角24，最近游玩、用户、设置多为16，小选择控件8；三个主页面的首屏标题结构不同。大面积灰色卡片让内容层级偏重的问题，已在上述同机对照中再次确认。

### 建议设计规格

下表为玩趣盒的提案参数，不是 ClashBox 的原值。

| 对象 | 建议规格 |
| --- | --- |
| 手机页面左右边距 | 16vp |
| 常规卡片 | 圆角20vp，内部16vp，无普通投影 |
| 横幅/大面板 | 圆角24vp，内部20vp |
| 内部控件 | 圆角12vp；胶囊另按高度取完整圆角 |
| 游戏网格 | 横12vp、纵16vp，手机2列；放大字号允许重排 |
| 内容分组之间 | 24vp |
| 区块标题到内容 | 8～12vp |
| 页面标题 | 28fp，统一三页位置与工具入口 |
| 区块标题 | 18fp Medium/Semibold |
| 游戏名称/设置标题 | 16～17fp |
| 重要说明 | 14fp |
| 时长、辅助元数据 | 12fp |
| 工具按钮触区 | 至少44×44vp |
| 设置行 | 最小56vp，有双行/放大字号时自然增高 |
| 按压 | 保留卡片0.98、按钮0.96 |
| 导航 | 保留现有HdsTabs；三入口稳定可见 |

浅色建议用轻底色配白/近白卡片，深色用更深底色配稍亮卡片。优先选择适合各角色的系统资源；系统资源在目标设备上不足以分层时，再配置应用base/dark资源。游戏图标和棋盘保留玩法颜色，其他大面积表面保持中性。

### 页面调整

**精选：** 增加统一页面标题；横幅缩成轻量介绍；最近游玩优先且可直接再玩；新玩法与热门游戏使用同一游戏卡规格。缩短目录里的规则说明，完整说明留在游戏内已有设置面板。冷启动无最近记录时用精简空态，不占大面积首屏。

**分类：** 增加统一标题；下方放48vp搜索栏，再放单行横向分类；当前分类数量单独展示。切换分类保持当前项可见，并明确是否回到列表顶端。点击切换为主；涉及横滑时要和外层分页手势做取舍，避免两层同时响应。

**我的：** 保留用户信息、四项统计、最近记录和排行功能，统一卡片规格。排行榜行与其他内容保持同一左边线；目前有页面16 + 列表外层16 + 行内16的累计48vp，建议去掉列表外层重复内边距。

**设置：** 按外观、游戏反馈、数据、关于分组；相关行共用一个容器，以轻缩进分割线组织。选中背景与系统强调色统一语义，修正少量仍固定蓝色的选择背景。保留动作行、跳转行、展开行现有不同箭头含义。

**游戏页：** 顶栏轻量、棋盘优先；沿用现有路由进入，运行游戏时不出现全局分页手势。设置面板和结算面板与首页使用同一表面/圆角/文字体系，继续保留已有暂停恢复、返回游戏固定按钮和进度保护。

### 实施顺序与代码映射

| 顺序 | 目的 | 主要文件 |
| --- | --- | --- |

| P1 | 统一三页标题和内容对齐线 | `FeaturedTab.ets`、`CategoryTab.ets`、`ProfileTab.ets`，按需新增共享页头 |

### 明确不建议迁移的部分

1. 滚目录就把底栏收成一个图标：会降低游戏分类的可发现性。
2. 代理持续开关、网络仪表盘和配置密集列表：玩趣盒没有同一任务模型。
3. 用自绘Swiper/Flex替换已存在的HDS原生悬浮栏：现有组件已经具备系统材质和适配基础。
4. 全页模糊、每张卡片投影、每个图标旋转进场：会争夺游戏内容注意力。
5. 动画不断改布局尺寸、固定卡片高度、按字数任意缩标题：不利于当前项目性能约束和字号适配。
6. 直接复制旧组件状态、兼容包装和二维类型实现：先保留当前ArkTS约束与项目架构，按需求实现同等设计意图。
