# 玩趣盒：鸿蒙激励资格与获奖能力差距分析

研究日期：2026-09-26。对象：当前工作区中的「玩趣盒」（LittleGames），13 款原生小游戏合集。本次只研究和提出修改建议，没有修改应用代码，也没有报名或提交应用。

## 结论

**先核实参评资格，再投入功能开发。** 2026 常规应用激励的「新应用」类别排除游戏 App。按当前产品形态，玩趣盒属于原生游戏合集；没有证据表明它已被华为认定为热门应用，因此不能把「达到 400 月活、10 个评分」当作本项目能领奖的路线。

如果目标是达到创新奖项或精品推荐的竞争水平，最值得投入的是：完整对局存档、每日益智挑战、服务卡片、真实手机到平板的对局接续，以及可解释的解题辅助。继续增加普通小游戏数量、单纯接入更多 Kit，缺少明显的获奖说服力。这是基于官方评审方向和当前工程的产品判断，并非华为承诺的获奖条件。

## 三、按价值排序的修改建议

### P0：决定资格与基础体验的修改

**A. 确认参评路线和发布范围。**

- 核对开发者主体、本人报名状态、热门应用查询结果、是否已正式上架以及当前协议期限。
- 按真实游戏合集形态查询应用市场审核要求；不要为了新应用激励将它改名为工具或教育应用。游戏具体资质以市场对应分类审核为准，本报告不判定某项资质对本项目必然豁免或必然适用。
- 当前 build-profile 中 compile/compatible/target 都是 API 24。评估目标用户设备版本与实际 API 依赖，确认是否值得兼容更早版本；不要直接降低 compatibleSdkVersion 而不检查能力可用性。
- 准备发布签名、真机安装包、统一新品牌截图与简介、素材来源/授权记录、可联系的反馈入口。现有关于页的数据说明应扩展为与实际功能一致的隐私政策；若以后接入联网、同步或 SDK，必须同步更新说明与权限。

**B. 保存完整对局，而不仅保存战绩。**

先覆盖数独、2048、华容道、滑动拼图：保存题目、棋盘、难度、步数、必要的随机状态和辅助操作记录。数独额外保存候选笔记；有计时玩法时明确暂停时间口径。存档带版本信息，升级后可迁移；损坏记录安全降级，不影响新开局。

首页新增「继续上次对局」，游戏入口允许「继续 / 新开」。后台冻结不能替代落盘存档，最高分恢复不能替代完整棋盘恢复。

验收：退出页面、系统回收、强制结束后重启、升级安装后恢复，棋盘和进度一致；新开局不误恢复旧档；清空游玩数据同时删除对应存档。

**C. 完成真机与可访问性验收。**

对 13 款覆盖首局、胜利/失败、重开、切后台、弹出退出确认、返回和再次进入。重点核对深浅主题、英文、大字体、屏幕阅读器、手机/平板/折叠屏运行中的布局改变。

动态游戏录制真实帧时间和长局表现；暂停/后台检查没有持续游戏循环；用同一设备对比温升、耗电和内存。现有期望 60fps 与桌面逻辑检查不能代替真机测量。所有性能数字在参评材料中注明设备、系统、构建模式和测量方法。

### P1：让用户愿意回来，并形成完整产品体验

**D. 每日益智挑战。**

优先以数独或滑动拼图做一个完整版本。通过日期与题号生成可重复的题面；同一题号保持规则和布局一致，日期切换保留已开局进度。每日挑战保存完成状态、耗时、步数和个人最佳；普通练习与挑战分开记录。

分享卡包含题号、成绩、游戏版本，朋友能进入同一题面。先支持离线题号挑战，不必为全球排行榜先建账号和服务器。若未来做竞技排行，再考虑公平规则、服务器校验和不同辅助模式的成绩分类。

验收：重新进入当天仍为同题；换日期不会覆盖未完成棋盘；两台设备输入题号得到一致题面；挑战结束状态重启后保留。每日挑战、分享和成就是产品建议，并非常规激励的官方必选功能。

**E. 桌面服务卡片。**

卡片显示「今日题目 / 完成状态 / 继续上局」，点击直达对应游戏或存档，避免只回首页。提供小尺寸版本，并适配深浅主题。卡片是信息和入口，不把整套棋盘玩法硬塞进卡片。

验收：应用进程不在时能正确拉起；参数能准确定位题目和存档；不同尺寸显示清楚；没有存档时入口有明确替代动作。

官方依据：[服务卡片设计指南](https://developer.huawei.com/consumer/cn/doc/design-guides/system-features-service-widget-0000002087671904)。

**F. 提示、撤销、首次教学与分游戏战绩。**

- 数独增加候选笔记、撤销、冲突定位及一次一步的推理解释；提示不只直接填答案。
- 华容道和拼图可先加可达性检查、撤销与下一步提示。
- 每款首次游玩给简短交互示例，设置中可重新查看。
- 不同游戏分别呈现最高分、最少步数或最短用时；不要把不同算法下的原始分数相加当成统一竞技排行。
- 成就可以围绕首次通关、个人最佳和连续完成挑战，不用无意义的点击签到替代真实游玩。

这些功能大多可先离线实现。规则求解器并不自动属于生成式 AI；若参评 AI 方向，材料必须说明实际模型能力和相对规则算法的增益。

### P2：真正提高创新奖竞争力的主打能力

**G. 手机到平板接续同一局。**

先用数独完成一个可演示的端到端场景：手机填到一半，切到平板保持同一题目、已填数字、候选笔记与步数；平板采用大棋盘加侧边工具，回到手机能继续。

存档快照是其前置基础。需要按照 HarmonyOS 官方应用接续/相关跨设备文档实现，并核实 API 24、设备与账号条件；本报告不声称 API 24 下所有目标设备都已具备同样能力。手机和平板分别运行同款应用、或各自保存最高分，不属于完整对局接续。

验收：两台实体设备录像展示状态一致；连接失败有可理解的恢复方式；接续不能重复计分或生成新题。多设备界面参照[华为多设备游戏指南](https://developer.huawei.com/consumer/cn/doc/doccenter-multi-device/bpta-multi_game)，应用接续场景参照[官方生态解决方案](https://developer.huawei.com/consumer/cn/doc/guidebook/solution8-0000002571173932)。

**H. 一个具有原创规则的招牌玩法。**

目前 13 款多数为成熟经典玩法。建议挑数独或华容道制作具有独特关卡机制、分层教学和可解释辅助的招牌模式，让评审能说清「为什么用玩趣盒」；不用先增加十几种同类游戏。

可选择「碎片时间益智、进度随设备继续」作为主线，把每日挑战、卡片、离线解释和跨设备接续组成一个用户旅程。这是建议定位，仍需真实用户反馈验证；不宣称医疗、认知改善或其他未验证效果。

**I. 小艺意图入口作为后续补强。**

在官方支持的意图类型和接入条件范围内，探索「打开今日挑战」「继续数独」等明确入口；先核对 Intents Kit 规范，不能假定任意自然语言句式都能识别或分发。简单拉起应用不等同于独立智能体，也不自动符合天工激励。

官方依据：[HarmonyOS 应用能力介绍](https://developer.huawei.com/consumer/cn/app/)、[Intents Kit 指南](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/intents-kit-guide)。

## 四、建议的实际开发顺序

| 阶段 | 交付内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| 资格与发布 | 确定可参加的计划/赛事、期限和分类；完成签名与目标设备范围 | 没有尚未确认的资格假设 |
| 基础体验 | 长局存档、继续对局、真机测试、完整隐私与反馈、主题和无障碍回归 | 长局不中断，主要路径可验证 |
| 用户回访 | 一款每日挑战、题号分享、服务卡片、解题辅助 | 可以展示从桌面到挑战再到继续的完整体验 |
| 创新主打 | 一个游戏的手机到平板接续，原创招牌模式 | 有实体设备演示和真实用户反馈 |
| 参评证据 | 对应当届规则的能力清单、测试报告、介绍与演示视频 | 每个宣称有可核实证据，按正式要求提交 |

如果只能优先做三件功能：**完整对局存档 + 每日挑战和卡片 + 数独跨设备接续**。前两项改善真实产品体验，第三项形成更有辨识度的鸿蒙创新演示。

## 五、暂不优先的投入

- 为数量继续堆相同经典玩法。
- 为接入数而增加广告、支付、定位、推送、账号等能力；按用户场景决定是否需要。
- 为「看起来先进」统一重写 3D 或加入没有作用的聊天机器人。
- 为排行榜先建设复杂后端；离线个人挑战可以先验证需求。
- 将已修复的性能问题重复当成待办，或用 60fps 期望值包装成真机实测成绩。

这些选择不会自动失去参评资格；只是当前项目阶段的投入优先级判断。

## 六、参评材料该证明什么

1. 用户是谁、在什么场景使用、现在遇到什么问题；有实际访谈或试用证据。
2. 核心体验演示：桌面进入每日题目，保存对局，平板接续，解释一步推理，完成挑战。
3. 鸿蒙能力与用户收益逐一对应，说明哪些已经实现、哪些尚为规划。
4. 签名包及可复现说明、多设备真机验收、性能测量方法、素材授权来源。
5. 留存、挑战完成率、真实评价等运营指标；这些用于产品评估，不自动等于某计划的官方门槛。

本次确认的极客赛道要求包括作品介绍、可运行演示及 1–3 分钟讲解视频；未来实际提交时必须重新以所报名赛道的当届规则为准。获奖名额与其他作品的竞争也影响结果，完成此清单不构成获奖保证。
