# 玩趣盒：真机与发布验收方案

制定日期：2026-09-26。本文是待执行的验收计划，不是通过报告。

## 当前起点

当前工程已经记录模拟器回归、149 项桌面逻辑检查及 API 24 构建通过；这些不能代替真机触控、渲染和功耗验收。签名配置为空。模块声明 phone 和 tablet，最低兼容版本为 HarmonyOS 6.1.1 / API 24。

完整棋盘存档尚未实现。当前强制结束后应验收最高分、次数、最近记录及设置是否保留；不能把恢复完整对局当作已有能力。新增存档后再增加相应恢复用例。

## 1. 设备与测试包

推荐设备组合：一台本人可长期使用的普通鸿蒙手机 + 一台折叠屏 + 一台平板。兼顾较窄手机窗口、折叠切换和大屏布局，设备系统必须满足 API 24 的最低要求。

预算有限时：保留一台实体手机供触控、震动、连续游玩、耗电和温升验收；通过 AGC 云测试/云调试补其他形态。先确认账号可用设备、API Level、测试额度，云端画面不能代替本地手感与真实触觉。

1. 固定一个待发布版本，记录源码提交或工作区快照、版本号、设备型号、系统/API、构建模式和测试包哈希。
2. 先用合法的调试/测试签名完成真机安装及问题定位。
3. 修复后用最终 Release 构建配置复验；性能结论注明构建模式，不能只测试 Debug 包后宣称发布版通过。
4. 正式上架时按 AGC 要求使用发布证书和发布 Profile 导出 APP 包；用于设备测试的签名包与市场提交包的签名用途要区分，核对代码、资源和配置对应同一候选版本。
5. 降低最低 API 版本属于另一项兼容改动，需先审查 API 使用并补测，不能只改版本数字扩大宣传范围。

## 2. 功能矩阵

普通手机对 13 款游戏逐一执行；折叠屏和平板至少逐一检查入口、首屏、操作区、返回和结果层，并重点执行窗口变化专项。发生某形态相关问题后，扩大该形态的回归范围。

| 用例 | 执行方法 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| 新安装与冷启动 | 全新安装，启动到首页，首次进入每款游戏 | 名称图标正确，无白屏、崩溃、无响应；首屏可操作 | 未执行 |
| 正常游玩 | 每款实际完成主要操作，测试支持的难度 | 手势/按钮准确，规则和计分正确，棋盘不遮挡按钮 | 未执行 |
| 结束路径 | 触发失败、通关或计时结束，按玩法适用 | 结算正确且可读；再来一局、返回可用 | 未执行 |
| 重开 | 进行中重开，快速连续点击，切换难度 | 无旧计时器、旧题目、旧动画影响新局 | 未执行 |
| 后台与锁屏 | 游玩中切桌面/锁屏 30 秒，再恢复，重复 10 次 | 无时间或位置突然跳变；手动暂停保持暂停 | 未执行 |
| 退出确认 | 打开弹窗、取消、确认退出、系统返回 | 动态游戏在弹窗下冻结；退出后不继续推进 | 未执行 |
| 本地数据 | 修改设置、创造有效成绩，切后台后强制结束并重启 | 已持久化设置和战绩保留；次数、最近记录正确 | 未执行 |
| 清空与重置 | 分别取消/确认清空游玩数据和恢复默认设置 | 两者作用符合说明，不误删另一类数据 | 未执行 |
| 离线与震动 | 飞行模式下游玩，开关震动偏好 | 离线游戏正常；震动可关闭，不支持震动不影响操作 | 未执行 |
| 外观与语言 | 深色/浅色、中文/英文、最大系统字体 | 文案完整、可读、无关键按钮遮挡或截断 | 未执行 |
| 无障碍 | 开启屏幕阅读器，操作首页、设置及重点益智玩法 | 焦点与描述正确；不能只依赖颜色区分状态 | 未执行 |
| 动态窗口 | 游玩中分屏、旋转、折叠展开/收起，重复切换 | 状态不意外重置；棋盘和触摸区域一致，控件仍可用 | 未执行 |
| 覆盖升级 | 安装前一测试版本并产生数据，再以相同包名和可升级签名安装候选版本 | 版本更新成功，设置与战绩保留 | 未执行 |

重点专项：

- 打砖块：挡板快速拖动、发射、漏球、下一关；连续玩 10–15 分钟。
- 跳一跳：蓄力、起跳、坠落时分别切后台；长局检查下一平台和内存变化。
- 贪吃蛇/俄罗斯方块：连续方向输入、加速下落、运行中重开、失败结算。
- 数独：快速切难度、出题中返回、缩放/复位；旧任务结果不得覆盖新页面。
- 消消乐：交换、连锁、结算中返回和重开；棋盘保持可玩。
- 2048/华容道：动画期间快速操作、弹出退出确认、改变窗口尺寸。

对无法覆盖的路径明确填「未执行」，不能用首屏检查代替完整玩法验证。

## 3. 性能测试

使用 DevEco Testing 的性能指标监控配合人工操作；需要定位卡顿时录制 trace 并使用 DevEco Profiler。自动遍历未必能深入解谜或通关，必须补人工场景。

| 场景 | 建议采集 | 主要判断 |
| --- | --- | --- |
| 冷启动/首次进游戏 | 启动和交互完成耗时，CPU、内存，截图 | 无明显长白屏、操作响应稳定；多次记录分布 |
| 打砖块/跳一跳连续运动 | FPS、帧间隔、卡顿 trace、CPU/GPU | 看运动是否稳定与长帧原因，不只看平均 FPS |
| 首页和各游戏往返 20 次 | 内存曲线、停留稳定后的占用 | 允许缓存和短期波动，不能持续累积不释放 |
| 暂停、退出弹窗、后台 | 应用 CPU 和线程活动 | 游戏循环停止，应用负载明显下降；不要求系统整体 CPU 为零 |
| 连续游玩 15 分钟 | 电量、温度、帧间隔、内存 | 无明显热降频导致体验恶化，与同设备基线比较 |

比较前后版本时固定设备、系统、亮度、刷新率、构建模式、网络和初始温度。每项至少重复三次；温升测试避免一边充电一边比较，短时电量百分比不能作为精确功耗结论。

项目自定的放行要求：本轮指定验收流程中崩溃和无响应为零；主要操作、返回和结果层无阻断；长局及重复进出不存在确认的持续内存增长；暂停与后台不存在确认的持续游戏循环。动画目标为稳定 60fps 的体验，但不得写成已达到 60fps，除非已有对应真机数据。

上述次数、时长与放行要求是本项目建议，不是华为统一审核阈值。

## 4. 发布前检查

- 包名与 AGC 应用记录一致；版本号正确；Release 配置、发布证书/Profile 与支持设备类型正确；正式包不含调试标志。
- 以真实游戏合集分类核对当前游戏发布及资质审核要求，准备版权/代理证明、备案等适用材料；具体材料以对应分类及当前规则为准。
- 应用名称、图标、介绍、截图、语言和支持设备范围与实际版本一致；使用新品牌和当前版本截图。
- 提供隐私声明地址或官方托管版本；与当前本地保存、无登录、不上传游玩数据及振动用途一致；说明本地数据清理与反馈渠道。
- 若接入联网、统计、崩溃监测或其他 SDK，重新核对实际采集行为、权限和隐私声明，不能继续沿用「不上传数据」的旧描述。
- 为审核人员提供游戏操作说明、触发主要结果的方法和已知限制。当前没有账号功能，不提供虚构测试账号。
- 执行 AGC 上架测试或 DevEco Testing 上架预检，保存报告；排除阻断问题后再提交正式审核。
- 给审核和驳回修复留出时间，至少提前一周更稳妥。正式审核通过并可下载后再记录为「已上架」。

## 5. 放行记录与交付物

建议给每个用例保存：设备/系统、候选版本、操作步骤、期望与实际结果、通过/失败/未执行、截图或录像路径、缺陷及复测结论。

最终保留四项：

1. 同一候选版本的签名发布包及版本记录。
2. 真机功能矩阵与窗口/无障碍录像。
3. 性能和上架预检报告，明确测量设备与限制。
4. 市场素材、隐私政策、适用资质和审核说明。

功能矩阵未覆盖、云测试报告未通过或缺陷尚未复测时，不写「真机验收完成」。发布后通过实际用户反馈持续收集问题；如选择 APMS，先完成相应接入与隐私核对。
