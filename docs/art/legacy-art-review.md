# 原有 33 款游戏：美术与交互特效检查

检查日期：2026-10-03。范围为最初的 13 款游戏及 Collection 的 20 款游戏。

结论：基础素材已经齐全，值得继续优化的是操作过程的可见反馈、少数场景的完整度，以及深色主题的材质层次。优先考虑打地鼠、记忆翻牌、消消乐；保留 2048、跳一跳和打砖块已有的动画基础。

首次检查完成源码检查、资源引用检查，以及 33 款游戏各一张浅色和深色历史设备截图的视觉复核，共 66 张。截图来源为 `docs/screenshots/accept-mate60-{light,dark}-*.jpeg`，文件日期为 2026-09-29 至 2026-09-30。本文末尾拼图仍是历史截图索引。首次检查时 `hdc list targets` 返回 Empty，当时只整理建议，没有修改游戏实现。

同日连接手机后已完成[本轮真机验证](../device-acceptance/art-review-2026-10-03/README.md)：33 款老游戏深浅色共 66 个新首屏复核，11 款 33 组选定交互通过。扫雷及双人玩家 2 获胜的庆祝遗漏已修复并在深浅色复测；89 项相关回归和 API 24 构建通过。其他美术升级仍是建议。未测帧率和真实触感。

## 实施边界与顺序

1. 扫雷和双人游戏的庆祝遗漏已修复。接下来补共享交互组件的按压回弹、选择高亮、局部正误/得分反馈。已有 `GameArtTile`、`ExpansionFeedback` 可参考，但后者参数依赖 `ExpansionViewModel`，应提取通用事件参数后再复用。
2. 先完成打地鼠和翻牌，再完成三消的中间状态播放；同时改数织线索对齐。这几项变化最容易被玩家感知。
3. 后续完善俄罗斯方块、棋类、汉诺塔的玩法动画及跳一跳的场景。2048 与打砖块保留现有实现，只添加局部效果。

具体实现遵守项目 ArkTS 规则：以响应式状态驱动 `translate`、`scale`、`rotate`、`opacity`，复杂整体变换使用 `renderGroup(true)`；不在动画过程中频繁改布局尺寸。三消等保留规则层的确定性，呈现层单独持有稳定棋子身份和阶段数据；动画期间的重复输入需要明确处理。所有暂态效果在暂停、退出、后台和重开时取消，续玩恢复不重播旧事件。

共享结果弹窗当前在出现时统一调用 `Haptics.success()`。后续可根据胜利、失败、暂停分别决定是否触发触感，并继续遵守现有触感设置。反应计时游戏在信号出现前不使用装饰过渡。

新增颜色和尺寸进入资源表；有语义的字符串补齐 base、zh_CN、en_US。深色实体素材按实际观感补齐，不把 43 个共用 `play_*` 素材全部重复生成当作目标。

后续升级验收关注：持续快速输入、最后一步结算与动画衔接、后台/重开取消、深浅主题的数字可读性，以及手机/折叠屏/平板窗口中的效果裁切。本轮庆祝参数修复已完成构建和相关回归，实际设备覆盖范围见上述真机报告。
