## ForEach 语义与刷新证据

依据[华为 ForEach 官方文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/arkts-rendering-control-foreach)，已存在的键复用既有组件；声明 itemGenerator 的 index 而未声明 keyGenerator 的 index 时，最终键包含框架补入的 index。因此不能把所有捕获 index 的回调一概判为错位。

本次区别三种情况：普通可变棋子快照用可观察包装；固定格子/槽位只捕获不变编号并读取当前状态；同 id 生命周期内不可变的家具对象按插入/移除更新。Idiom 的选项重排属于框架带 index 的键规则，已核对，不增加绕路修复。

`scripts/test-expansion-render-audit.cjs` 在本次复查后 **14/14 通过**。它验证真实 ViewModel 的当前快照、保留包装身份、消失对象移除和撤销恢复，没有声称执行原生 ForEach。已删除末项大量 `source.includes` 的实现镜像断言；修正拆螺丝测试把 id 当数组索引的问题；方块托盘检查标题明确为快照消费/补充，避免把模型断言称为原生按钮验收。

本次收尾复查无需新增生产 UI 改动。统一回归、API 24 构建和实机状态由 [总报告](README.md) 记录。
