# LittleGames 修复计划（2026-09-21）

> 基于 2026-09-21 代码分析得出。上一轮评审（`docs/project-review.html`，2026-09-01）的 P0/P1 已基本修复，
> 本轮聚焦该轮**遗留项**与**评审未覆盖的新发现**。

## 〇、前置验证结论（已对照本地 SDK 类型定义确认）

### V1. 游戏页的 onPageShow()/onPageHide() 是死代码，「切后台自动暂停」从未生效 ⚠️
- **证据**：SDK 声明 `sdk/default/openharmony/ets/component/common.d.ts` 第 30576 行明确注释：
  `onPageHide ... It works only for the custom components decorated by @Entry.`
- **现状**：10 个游戏页均为 `@ComponentV2`（作为 `NavDestination` 内容使用，非 `@Entry`），
  页面里定义的 `onPageHide()/onPageShow()` 方法**永远不会被框架调用**。
- **后果**：
  - 贪吃蛇/俄罗斯方块/打地鼠切后台后定时器继续跑（蛇在后台撞墙、倒计时后台耗尽）；
  - 扫雷后台计时虚增（直接破坏「用时越短分越高」的得分口径）；
  - 所有 ViewModel 中为此写的 `autoPaused` 自动恢复逻辑形同虚设。
- **注**：上一轮报告 P0-7 的修复方向（补生命周期钩子）因用错钩子而实际未生效。

### V2. vibrator 使用需声明 ohos.permission.VIBRATE（system_grant）
- **证据**：`sdk/.../api/@ohos.vibrator.d.ts` 第 48/60/72 行标注 `@permission ohos.permission.VIBRATE`；
- system_grant 权限，在 `module.json5` 的 `requestPermissions` 中声明即可，无需用户授权弹窗；
- API 签名：`startVibration(effect: VibrateEffect, attribute: VibrateAttribute)`，
  本项目使用 `VibrateTime`（`{ type: 'time', duration: number }`）+ `{ usage: 'touch' }`。

## 一、修复项清单

### F1（P0）中途退出丢当前得分 + 切后台暂停失效
**问题**：
1. 分数累积型游戏（贪吃蛇/俄罗斯方块/2048/打地鼠）只在对局结束或下一次开局时结算
   （`gameOver()` / `startGame()` 里的 `updateHighScore`），中途点返回退出时
   `aboutToDisappear → dispose()` 只停定时器，**当前 score 从未写入数据层**；
2. 切后台后进程被杀，分数同样丢失（`onBackground` 的 `flushNow()` 只会刷出旧值）；
3. 由 V1，切后台自动暂停实际失效。

**方案**：
- 新增 `common/GameLifecycleBus.ets`：模块级单例 + `GameLifecycleObserver` 接口
  （ArkTS 禁用 globalThis，用显式模块单例）；
  - `attach(observer)` / `detach(observer)`：游戏页 `aboutToAppear`/`aboutToDisappear` 调用；
  - `notifyHidden()` / `notifyShown()`：由 `EntryAbility.onBackground()/onForeground()` 调用；
- 10 个 ViewModel 实现接口（语义分两类）：
  - **有定时器 4 款**（蛇/方块/打地鼠/扫雷）：`onAppHidden()` = 暂停 + `pauseTimer`（扫雷）+ 结算当前分；
    `onAppShown()` = 按 `autoPaused` 恢复；
  - **无定时器 6 款**（2048/数独/拼图/华容道/猜数字/翻牌）：`onAppHidden()` 仅结算当前分（若有）；
    `onAppShown()` 空实现；
  - 所有 VM 的 `dispose()` 追加结算当前分（覆盖「中途退出」主路径；updateHighScore 为 max 语义，幂等）；
  - 扫雷/数独等「完成才计分」的游戏结算为 no-op（无未落袋分数）；
- 删除 10 个页面里失效的 `onPageHide()/onPageShow()` 方法，替换为总线 attach/detach。

**涉及文件**：`common/GameLifecycleBus.ets`（新）、10 个 ViewModel、10 个游戏页、`EntryAbility.ets`。

**验证**：单元测试扩展 `ViewModelClassic/Puzzle.test.ets`——
`vm.newGame(); vm.onAppHidden(); vm.dispose()` 后 `GameDataManager` 分数已更新；
ViewModel 需暴露可测的结算查询（或经 GameDataManager.getGameById 断言）。

### F2（P0）对局进行中返回无确认（含系统侧滑返回）
**问题**：`GameHeader` 返回键直接 `pop()`；系统侧滑返回也无拦截。进行中对局一触即丢。

**方案**：
- 各 VM 增加 `@Trace confirmExit: boolean` 与 `requestBack(): boolean`：
  - `status === PLAYING` → 置 `confirmExit = true`，返回 `true`（拦截）；
  - 其余状态返回 `false`（放行；PAUSED 已由 F1 的 dispose 结算兜底，不重复打扰）；
- 新增 `components/ExitConfirmDialog.ets`（复用 GameResultDialog 的视觉语言）：
  「退出本局？当前成绩将保留」/ 继续（返回游戏）/ 退出（结算并 pop）；
- `GameRoutes.GamePageMap` 的 `NavDestination` 增加
  `.onBackPressed(() => GameLifecycleBus.notifyBackRequested())`（转发给活跃 VM）；
- 页面 `GameHeader` 的 `onBack` 回调改为走 `viewModel.requestBack()` 判断。

**涉及文件**：`router/GameRoutes.ets`、10 个 ViewModel、10 个游戏页、`components/ExitConfirmDialog.ets`（新）。

### F3（P1）触感反馈 + 开关持久化
**问题**：全项目 0 处震动/音效，休闲游戏核心反馈通道缺失。
（音效需要音频资源文件，本轮不做，见「暂缓项」。）

**方案**：
- `module.json5` 声明 `ohos.permission.VIBRATE`（V2 验证结论）；
- `GameDataManager` 增加 settings 存储（`KEY_SETTINGS` JSON）：`hapticsEnabled`（默认开）；
- 新增 `common/Haptics.ets`：`tap()`（10ms 轻震）/ `success()`（40ms）；
  开关关闭或设备不支持时静默跳过（catch 所有失败，不影响游戏流程）；
- 接入点（克制，避免过度震动）：
  - `ControlPad` 方向键 → `tap()`
  - `WhackMolePage` 敲中地鼠 → `tap()`
  - `GameResultDialog` 出现时 → `success()`
  - `MemoryCardPage` 翻牌 → `tap()`
- `ProfileTab` 新增「触感反馈」开关行（Toggle），读写 `GameDataManager` 设置。

**验证**：真机/模拟器手动验证震动；开关关闭后无震动。

### F4（P1）排行榜分数单位（scoreLabel 备而未用）
**问题**：P0-10（上轮）已为 `GameInfo` 增加 `scoreLabel`（分/步/次/秒 口径），但 UI 未消费：
- `ProfileTab` 排行行、`Index.bestScoreText` 都是裸数字；
- 华容道「步数换算分」与贪吃蛇「得分」混排时语义不清。

**方案**：
- `ProfileTab` 排行行分数后追加 `resolveString(game.scoreLabel, ctx)` 单位文本；
- `Index.refreshScores()` 生成 `bestScoreText` 时带上榜首游戏单位。

### F5（P1）无障碍覆盖补全
**问题**：现有覆盖（数独/扫雷/打地鼠格子、ControlPad、GameCard）之外仍有缺口：
GameHeader 四个图标按钮、GameResultDialog 按钮、2048 方块、猜数字键盘、
记忆翻牌卡、华容道棋子、滑动拼图块——读屏下全是无名元素。

**方案**：补 `accessibilityText`；新增 a11y 字符串资源（base/zh_CN/en_US 三处同步）：
- 通用：返回 / 难度设置 / 暂停 / 继续 / 重新开始 / 再来一局 / 退出弹窗按钮
- 2048：`第 %1$d 行第 %2$d 列，数值 %3$d`
- 猜数字键盘：数字 / 删除 / 提交
- 翻牌：`第 %1$d 张，已翻开` / `第 %1$d 张，未翻开`
- 华容道棋子 / 滑动拼图块：`%1$d 号棋子` / 位置描述

### F6（P2）ProfileTab 排行 List 硬编码高度
**问题**：`.height(312)`（6 项 × 52 的巧合值），改 TopN 或行高即错位。
**方案**：`List` 改 `Column + ForEach`（内容自适应，同时消除 Scroll 内嵌滚动容器隐患）。

### F7（P2）README 与现状不符
**问题**：README 仍描述已删除的 `NumberKeyboard.ets`、`GameOverDialog.ets`（实为 GameResultDialog）、
`ProfilePage.ets`、「媒体查询 ≥840vp 切宽屏版式」（isTablet 已删）等。
**方案**：同步项目结构、组件清单与多端适配描述；补充本轮修复说明。

## 二、本轮暂缓项（含理由）

| 项 | 理由 |
|----|------|
| 游戏音效 | 需要音频资源文件（rawfile），项目无现成素材；先落震动，音效待素材到位后接入 Haptics 同层开关 |
| compatibleSdkVersion 降级（上轮 P2-11 前半） | 需逐一核对全部 API 的 @since（Navigation/@ComponentV2/SymbolGlyph/Preferences…），风险高，需专项验证后再动 |
| 贪吃蛇/方块 Canvas/@Reusable 重构（上轮 P2-3） | 收益需真机实测佐证，重构风险与收益不成比例；先落 F1~F5 的确定性修复 |
| 数独 taskpool 化 | 位掩码优化后困难档 p99 ≈ 82ms，已低于可感知阈值 |
| release 签名/上架物料 | 需要用户提供证书材料，属签名专项流程 |

## 三、回归验证计划

1. **编译**：`hvigorw.js assembleHap --mode module -p product=default --no-daemon`（AGENTS.md 命令）零错误；
2. **单元测试**：扩展/更新 ViewModelClassic.test.ets、ViewModelPuzzle.test.ets 覆盖新结算逻辑；
3. **手动回归点**：
   - 贪吃蛇玩到中途点返回 → 首页「我的」最高分已更新；
   - 对局中侧滑返回 → 弹确认；确认退出 → 分数保留；
   - 切后台 5 秒回前台 → 蛇/地鼠处于暂停态（而非已死亡/倒计时耗尽）；
   - 扫雷中途切后台 30 秒 → 回来后计时未虚增；
   - 「我的」页排行显示单位；触感开关关闭后方向键无震动。
