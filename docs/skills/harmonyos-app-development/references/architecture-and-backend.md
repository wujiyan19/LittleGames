# 架构、数据与后端

## 现状与可泛化边界

LittleGames 是 HarmonyOS 原生客户端，业务规则和持久化都在设备端；LAN 房主承担一局内的权威状态。仓库没有云端 HTTP 服务、账号系统或远程数据库。

本文“本地、生命周期、接续、LAN”部分提炼已有实现；“配套云端后端”是基于这些边界提出的新功能默认建议，不是项目现状，也不指定服务端语言、框架、云厂商或部署平台。

## 职责分层

| 层 | 职责 | LittleGames 例子 |
| --- | --- | --- |
| Ability / 应用壳 | 初始化系统服务、窗口/安全区、应用生命周期、导航装配 | `EntryAbility.ets`、`pages/Index.ets` |
| 页面 / 组件 | 渲染、输入和业务事件，布局与动效 | `pages/home`、`components/GameCard.ets` |
| ViewModel | 响应式 UI 状态、用例编排、异步代次与暂停语义 | `viewmodel/SudokuViewModel.ets`、`CollectionViewModel.ets` |
| Model / 规则 | 业务状态与规则、生成和合法性判定，不依赖页面 | `model/game`、`RandomSource.ets` |
| 本地数据服务 | 数据读写、偏好、记录口径、刷新 | `model/GameData.ets` |
| 系统与传输适配 | 官方 API、网络帧、资源句柄、接续边界 | `common/LanTransport.ets`、`AppContinuation.ets` |

保留现有目录和服务入口；复杂度确有需要时拆分。新领域可按功能组织，不要求复制游戏目录。共享 Model 不 import 页面/Navigation，纯规则不读存储或发网络；随机源和时钟在需要可重复验证时可注入。

普通接口对象不会自动具有深层响应式语义。采用 `@ObservedV2` / `@Trace` 类，或沿用已有整体数组替换策略；修改嵌套数组后验证实际视图刷新。`ForEach` 使用稳定业务 ID；只有确认观察边界不足时加入有含义的版本键，不用随机键掩盖问题。

路由使用明确注册映射，未知 ID 显式处理，不跳到任意默认业务页。导航由壳/父页面持有；组件向上发事件，不自建隐式页面栈。

## 本地数据

- Preferences 适合少量偏好和轻量摘要。沿用已有 GameDataManager，不把它重写为第二份状态中心。新工程的数据量、查询和事务需求超过此边界时再评估官方数据库。
- 稳定 ID 标识业务对象；区分游戏总数、已玩数量、最高分、最近时间、累计时长等口径。时间单位明确，如 `playTimeMs`；展示层单独格式化和本地化。
- 内存更新后标记 dirty，短窗口合并连续写入。后台、接续导出等关键边界清理防抖并完成待写入数据落盘；避免每帧序列化完整数据。
- 异步 flush 失败保留待写入标记并记录必要错误信息；界面不要显示虚假的持久化成功。默认值用于缺失或可恢复的损坏数据，不能吞掉所有异常使故障无迹可查。
- 新增持久化结构时定义版本、缺省值与旧数据迁移；已有字段保持兼容。读取先校验类型、有限数字/范围、数组长度、枚举和 ID，再构建可用状态。
- 清空业务记录与恢复偏好独立，按产品语义说明范围。测试重启后保留、缺失键、损坏 JSON、失败写入和迁移；不因一种字段损坏删除全部有效数据。

普通偏好存储不承担服务端密钥存放职责。新增需要凭证的功能时核实平台安全存储能力，不把服务器密钥、签名私钥或数据库凭证放入客户端资源、仓库或日志。

## 生命周期与异步

`@ComponentV2` 放在 NavDestination 中时，不能把仅对 `@Entry` 有效的 `onPageShow/onPageHide` 当成业务生命周期。已有项目通过 UIAbility 前后台、NavDestination 可见性/返回事件与 `GameLifecycleBus` 显式连接；用目标 SDK 确认具体事件。

- 区分前台、页面可见、设置遮挡、手动暂停、自动暂停与结束状态。结束/隐藏时结算必要指标，停止计时、AI、音效和输入；只在状态允许时恢复。
- 当前总线只持有一个活跃游戏观察者；detach 校验实例身份，避免旧页面销毁移除新页面订阅。多活跃页面产品需要适合自己的生命周期范围，不照搬单观察者假设。
- 每次重开、切难度、切业务、退出或断开都会使旧异步代次失效。回调在 await 后和提交前检查 generation；失败与 finally 也不能改写后来一次请求的状态。
- 长计算使用已核实的 taskpool/并发接口；不在 UI 线程长期阻塞。计时器/Socket/监听有明确 owner，在业务结束或组件销毁时清理。
- 长时长使用明确且适合平台的时钟语义，暂停与后台区间不混入有效业务时长；实时循环限制异常大 dt，碰撞/采样避免跨帧跳过关键状态。
- 结算写记录、发送操作和关闭回调均只执行一次，快速双击不能重复提交或穿透到新界面。

## 序列化与设备接续

定义命名 DTO，只包含数值、布尔、字符串与其数组/明确结构，不含计时器、函数、资源对象、UIContext 或原生句柄。

按版本、载荷大小、路由白名单、ID、状态范围和领域不变量校验；复杂状态还需检查数组长度、棋子/格子一致性、当前阶段和操作合法性。`JSON.parse(...) as SomeDto` 只提供静态类型，不能证明数据可信。

先完成校验与候选状态构建，再一次提交恢复；失败不留下半恢复状态。必要 UI/服务未就绪时可保存待恢复载荷，但消费与错误回调只能发生一次。实时对局恢复后先暂停，待用户明确继续。

当前应用接续通过 UIAbility 与 Want 迁移必要导航和对局状态；设备接续不是云端实时同步。当前 LAN 对局不参与跨设备接续，不能迁移原生连接句柄。

## 已有 LAN 后端边界

LAN 功能适用时复用 `LanGameSession`、`LanProtocol`、`LanFraming`、`LanTransport` 与适配接口，而不是每个页面直接调用 Socket。

- 房主维护唯一状态，加入者发送意图，校验后以房主快照更新。确认角色、当前回合、结束状态、索引范围与动作合法性；客户端不能替对方操作。
- 包包含协议版本、业务 ID、对局编号、状态 revision、请求 sequence。拒绝重复、旧局迟到、游戏不匹配和非法动作；重开需要双方准备，确认后才进入新局。
- TCP 保证字节顺序，不保证一次 message 就是一帧。当前协议使用换行分帧，维护跨回调缓冲，正确处理拆包、粘包和 UTF-8；完整帧字节上限 131072，协议还单独限制 payload 字符串长度。
- 当前仅私有 IPv4，固定端口 41237，一房主一加入者，无账号、自动发现或断线续局。该端口与功能限制属于 LittleGames；其他产品依其协议配置。
- 发送串行队列限制积压；握手/连接/失联均有超时。关闭使旧 generation 失效，保留原生 peer 至异步发送结束并释放监听、缓冲和句柄。
- 当前后台主动断线，失联冻结输入并给出本地化恢复操作。不能声称此实现具有加密或互联网对抗能力；跨网或在线服务另定义传输、身份和信任边界。

## 配套云端后端：有需求时采用

先读取实际服务端与接口文档。已有契约沿用，纯后端规则采用其语言和框架惯例，不套用 ArkTS 限制。小应用先实现完成当前用例需要的最小服务；不默认新建微服务、账号、排行榜或云同步。

### 前后端契约

在实现前明确下面与用例有关的字段/语义，可用现有 OpenAPI、命名 DTO 或项目接口规范承载：

| 契约项 | 需确定的含义 |
| --- | --- |
| 资源 ID | 稳定字符串或现有约定，不用可变显示名作主键 |
| 字段与缺省 | 明确可空/可缺省、枚举、范围和数组上限 |
| 时间与数量 | 明确毫秒或 ISO 时间、时区、分数/金额/数量单位 |
| 列表 | 稳定排序、分页方式、页大小上限、空结果与结束标记 |
| 成功与错误 | 沿用 HTTP 状态及现有 envelope；稳定机器错误码与必要诊断 ID |
| 写入 | 操作合法性、幂等键/去重范围、事务边界和重复提交结果 |
| 并发与同步 | revision/条件更新或实际冲突策略，删除标记与版本兼容 |
| 权限 | 身份来源、资源归属、角色和允许操作 |

响应由客户端服务适配为本地 UI 状态；稳定错误码映射资源文案，不直接显示服务器堆栈或未经本地化的内部 message。示例 DTO 并不构成必须采用的新接口格式。

### 服务端责任

Controller/Handler 校验输入和身份，业务 Service 校验领域规则，Repository 负责实际存储。对当前需要原子性的写入使用真实事务或等效保证；重要动作由服务器重新判断，不能信任客户端上报的角色、总分或拥有者。

读请求与写请求明确区分。重复写有定义的幂等语义，冲突有明确响应；状态操作需要按资源归属授权。长期凭证与服务端密钥由实际环境配置注入，日志只记录必要的错误与关联信息。

### 鸿蒙客户端接入

通过单一服务适配边界使用已核实的官方 HTTP/WebSocket 能力；Native 请求对象及时释放。连接/读取超时、页面关闭取消或代次失效都需处理。离线、超时、未授权、冲突和服务器故障形成用户可理解的状态。

重试必须有次数/时间边界；只有安全读取或具有明确幂等保证的写入才可自动重试。鉴权刷新若需要则合并并发刷新，失败回到可恢复状态，不形成无限循环。

若要求离线写入，定义有界队列、去重、冲突和重放条件；若未要求，失败时保留可编辑输入并给重试，不默认添加复杂同步引擎。只读缓存说明过期与刷新方式；成功服务器响应提交后再更新权威本地状态。

### 联调与完成标准

用固定 fixture/本地服务验证 DTO 解码、分页、错误映射与竞态；用实际服务验证成功、非法字段、越权、重复写入及冲突等本次功能关键路径。把模拟、开发环境和真实服务结果分开记录；上线与环境改动按用户本次授权执行，不从“编写应用”推导发布范围。
