# 鸿蒙应用默认开发风格

将玩趣盒的原生体验与工程约定用于新的鸿蒙应用及现有应用扩展：清楚的内容层级、轻量实体卡片、系统语义色、自然的交互反馈，以及可验证的数据和业务逻辑。

这些是用户的默认偏好。用户本次要求与目标项目的 `AGENTS.md` 优先；已有设计系统、SDK、服务端技术栈和数据契约应沿用。不要为了套用此 skill 改写整个应用。玩趣盒的品牌、游戏内容、三栏名称和 LAN 端口不是所有应用必须采用的配置。

## 开始开发

先确认目标工程、已有未提交改动、模块与资源结构、SDK/API Level、状态管理版本、导航方式、数据存储和实际后端。需要新增依赖、权限或接口时先查现有实现与官方定义；不确定的 HarmonyOS API/语法应搜索华为官方文档，并核对目标 SDK 声明、导入、设备支持与权限。

读与本次工作相关的参考资料：

- 写 `.ets` 或 ArkTS 共享代码前，读 [ArkTS 与 API 约束](references/arkts-and-api.md)。
- 做页面、组件、素材或动效时，读 [界面与交互](references/ui-and-interaction.md)。
- 做状态、业务、本地存储、接续、联网或配套服务端时，读 [架构、数据与后端](references/architecture-and-backend.md)。
- 构建、测试和交付时，读 [构建验收与来源](references/validation-and-sources.md) 的相关部分。

对于 LittleGames，直接复用 `DesignTokens`、`HarmonyMotion`、现有公共组件、路由注册及数据服务。对于新工程，按功能需要建立相同职责的最小实现，不把 LittleGames 当作运行依赖。

## 默认前端

- 采用 HarmonyOS 原生组件与 Navigation；新工程在目标 SDK 支持时优先 ArkUI V2。组件负责展示和事件，ViewModel 编排状态，Model 承担可测试规则。
- 应用外壳使用系统背景、文字色与强调色；主卡浅色白、深色中性灰。业务插画和棋盘拥有独立双主题资源。主内容与控件分层，只有浮层使用轻投影和按需材质。
- 共享页头、卡片、分组、设置行和确认弹层。沿用统一圆角、间距、字体、触区和主次按钮关系，避免每页自建一套样式。
- 文案、颜色、新增尺寸与动效参数资源化；同时维护目标工程所有语言目录。默认支持跟随系统、浅色、深色，并保存用户选择。
- 从当前内容区域的可用宽高计算布局；覆盖小窗、分屏、横屏、平板、长文本和放大字号。控件最小触区与文字自然增高兼顾。
- 原生按压、物理弹簧选中、独立遮罩淡入和快速退场构成默认反馈。仅动画变换与透明度等合适的非布局属性；复杂动画子树使用 `renderGroup(true)`。
- 页面明确显示加载、内容、空态和失败，提供与业务对应的重试。保留筛选、返回和滚动位置等用户上下文。

## 默认业务与后端

玩趣盒实际拥有本地业务与数据层、设备间接续、LAN 房主/客户端；没有云端服务端。新任务未要求远程服务时，保持核心功能本地可用。需要云端时扩展现有业务边界，沿用目标后端技术栈；不得把建议的云端契约描述成已实现能力。

- 页面不直接访问数据库、Preferences 或 Socket/HTTP。通过已有服务边界访问；仅在确有第二种数据来源或复用需求时增加 Repository。
- UI 状态与序列化业务状态分开。外部 JSON 按明确 DTO 解析并逐字段校验，`as` 不替代运行时校验。
- 数据使用稳定 ID、明确单位与版本。持久化合并频繁写入，在后台等关键边界保证待写入数据落盘；损坏输入与写入失败可定位且不伪报成功。
- 异步生成、请求与联机回调支持取消或代次检查；旧请求不能覆盖新状态。页面销毁和业务结束清理计时器、监听与原生句柄。
- 生命周期显式连接 UIAbility、NavDestination 和业务服务。暂停、设置遮挡、后台、返回、重开及恢复具有一致语义；只恢复自动暂停，不解除用户手动暂停。
- 接续与同步只传必要的可序列化值，先验证版本、范围和业务一致性，再提交恢复。联机状态由房主或服务端权威管理。
- 新增配套服务端时，先定 DTO、错误码、鉴权/资源归属、分页、时间单位、幂等和冲突语义，再实现双方。错误码由客户端映射多语言文案，业务核心保持可独立测试。

## 推进与验收

先完成一条用户可用的端到端流程，再按已有组件和服务边界扩展。保持改动范围与任务一致；不创建无使用者的抽象、兼容层或云端基础设施。

按改动选择有意义的规则、存储、生命周期或协议测试；`.ets` 修改还需目标 SDK 原生构建。前端变更应检查双主题、关键操作、适用窗口和字号；联网变更覆盖超时、乱序/重复、取消与断线。设备不可用时明确记录未实测项，构建与桌面测试不能替代设备验收。

交付说明具体行为、变更位置、已运行检查及实际限制。涉及后端时区分模拟联调与真实服务验证，不从历史报告继承“已通过”的结论。
