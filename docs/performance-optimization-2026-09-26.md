## 可确认的结果

- 14 张图片合计从 **15,978,850 字节（15.24 MiB）降到 1,044,578 字节（约 1.00 MiB）**，减少 **93.46%**。已检查缩略尺寸下前后对比。这是资源文件大小，不是实测进程内存降幅。
- 默认窗口与普通难度下连续模拟 **1000 次成功跳跃**，平台始终不超过 **15 个**，分数和当前/下一平台识别正确。原检查保留了 1008 个平台。
- 暂停、后台、确认弹窗和销毁时，相关游戏的计时器或帧源停止；主动暂停不会因切回前台自动恢复。
- 打砖块以同一随机种子比较按帧运行与原 30ms 手动物理步进，球状态一致；插值、拖动后发射首帧、漏球待发及关卡切换均有回归检查。
- **149/149 项桌面逻辑检查通过**：123 项现有模型/ViewModel 检查及 26 项新增性能回归。现有贪吃蛇测试适配已有的三节初始蛇；消消乐测试改为寻找棋盘实际可消除的一步，不再依赖旧生成策略的固定坐标。
- API 24 DevEco 工程 **assembleHap 构建成功**；`git diff --check` 通过。构建仍有既有字符串 API 警告，工程尚未配置签名。

新增桌面回归覆盖：计时器生命周期、倒计时剩余时间、逐格数据一致性、食物满盘处理、显示时间戳与恢复、物理插值和补步上限、平台长局、后台冻结、退化随机源、500 种子可玩棋盘、数独乱序结果与失败、持久化防抖及失败重试、图片尺寸和多语言文案。

## 真机验证边界

当前没有连接 HarmonyOS 设备，因此没有测量优化后的帧率、掉帧比例、CPU/GPU 占用、功耗或温度，也没有完成真机点击/手势验证。60fps 是帧源的期望与上限，不是实测帧率保证。

设备验收建议用同一设备、构建模式、亮度和初始温度，比较优化前后：

1. 打砖块连续运行 3–5 分钟，检查帧时间、布局、GC、碰撞和挡板拖动。
2. 游戏分别暂停、打开退出弹窗、切后台，再恢复，确认循环停止且没有加速或时间跳变。
3. 检查 2048 动画点击、数独缩放中心/双击复位、华容道操作，以及跳一跳长局下一平台定位。
4. 冷启动和首次进入分类页检查图片解码与内存峰值；游玩 10–15 分钟比较温升和耗电。

设计依据参见[原检查报告](performance-review-2026-09-26.md)中的官方资料链接。优化目标是减少布局、重复计算、闲置回调和解码负担；帧率与温升改善幅度需由上述设备数据确认。
