### 关键结论（后续改动需留意）
- **@Local 只做一层代理**：二维数组内层赋值（`board[r][c] = v`）、数组内对象字段赋值（`block.x = nx`、`card.flipped = true`）**不会**触发 UI 刷新。数独是明确 bug；华容道/滑动拼图/记忆翻牌靠同函数内的顶层赋值"顺带"刷新，属脆弱隐式依赖。修复方向：`@ObservedV2` + `@Trace`，或统一不可变更新。
- **LightColors 与 DarkColors 内容完全重复**（均引用同一批 `$r('app.color.*')`），主题适配实际由 `resources/base` 与 `resources/dark` 完成。计划合并为语义令牌。
- 数独 `generatePuzzle()` 在主线程做全量回溯求解，困难档（23 线索）可达数秒，跳转即卡死 —— 最高优先级性能问题。
- `GamePanel.ets` 是死代码且内含 `getRouter().back()`，与项目 Navigation/NavPathStack 体系冲突，不可误用（待删）。
- `GameStatus` 枚举已定义但全项目未使用，各页用 isPlaying/isPaused/isWin 三布尔拼状态。
- 全项目 grep：`renderGroup` 0 处（违反 AGENTS.md）、`expandSafeArea` 仅 Index.ets 1 处（10 个游戏页全缺安全区适配）。
- `GuessNumberPage` 是唯一未接入 `GameDataManager` 的游戏。
- 硬编码颜色 40+ 处，最严重是 2048 调色板（深色模式下白字配浅底不可读）。

## 修复：华容道 / 滑动拼图 / 记忆翻牌 同类嵌套赋值（P0-1 续）

统一采用不可变更新（copy-on-write），与数独保持同一套写法，不引入新装饰器。

- **`KlotskiPage`**：`blocks` 是 `BlockInfo[]`（对象数组），原 `block.x = nx` 改不动。新增 `rebuildBlocks(movedIdx, nx, ny)` 重建整个数组后整体赋值。`moveBlock` 改用索引定位，`grid` 占据判断的 `if (grid[r][c] && ...)` 改为显式 `!== null`。
- **`SlidePuzzlePage`**：`board` 由 `number[][]` 改 `number[]`（n*n）。`findZeroRow/Col` 合并为 `findZeroIndex()`，新增 `cellAt(r,c)`。`tapCell` 复制后整体赋值；`startGame` 先本地组装 `flat` 再赋值（原来 `this.board.push(row)` 会触发 n² 次）。
- **`MemoryCardPage`**：`cards` 是 `CardInfo[]`（对象数组），原 `this.cards[i].flipped = true` 改不动。新增 `cloneCards()` + `setCardFlipped` / `setPairFlipped` / `setPairMatched` 三个整体赋值入口。注意 `cloneCards` 里是**逐字段新建对象**，避免新旧数组对象别名。

**验证**：`assembleHap` BUILD SUCCESSFUL（13s），无新增 error/warning。

### 全项目嵌套赋值排查结论（重要，后续改动前先看这里）
逐个确认了其余页面的 `this.xxx[r][c] = v` 写法，**目前都能工作但机制不同**：
- `MinesweeperPage`：`revealed` / `flagged` 本来就走 `copyBoolBoard` + 整体赋值，是对的；`board` 只在 `placeMines` 里改一次，而 `reveal()` 后面必然有 `this.revealed = nr`，能带出刷新 → 安全
- `TetrisGamePage`：`lock()` 里改 `this.board[y+r][x+c]`，但紧接着 `clearRows()` 无条件 `this.board = newBoard` → 安全
- `Game2048Page`：`addRandom()` 里改 `this.board[r][c]`，靠同一函数的 `this.tiles[pos.r] = row`（**外层下标赋值**）带出刷新 → 能工作，且说明 V2 下「一维/外层下标赋值」是可观测的
- `KlotskiPage.buildGrid()` 写 `this.grid[r][c]`，但 `grid` 是普通私有字段、不参与观测，且每次都紧随 `blocks` 变更重建 → 安全

即：**全部 4 个已修页面 + 2048 原本都是靠"同函数里恰好有另一次可观测赋值"侥幸刷新的**。现在 4 个已改为自洽。2048 / 俄罗斯方块 / 扫雷仍是脆弱隐式依赖，重构时容易静默失效，可选后续加固。
